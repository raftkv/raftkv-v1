> **范围**: batch1已证功能正确（19/19 PASS），batch2证稳定性根治与性能达标。
> **结构**: 两段——P-Ⅰ稳定性根治先行，P-Ⅱ性能压测后置。
> **状态**: 起草，提交后停机等批复。P-Ⅰ根因分析（只读诊断）可在批复前先启动。

## P-Ⅰ 稳定性根治

### 目标

E02实测分区恢复追平耗时35s（追12条日志），疑似Raft同步参数偏保守。
P-Ⅰ通过根因分析→修复→回归，将收敛耗时降至≤5s或给出归因。

### R-01 Raft参数根因（35s收敛追因）

| 项 | 内容 |
|---|---|
| **目的** | 定位35s收敛的根因：心跳间隔/选举超时/AppendEntries批量/snapshot触发等 |
| **步骤** | 1. 只读诊断：读取raft.go中心跳/选举/AppendEntries参数<br>2. 分析E02 timeline.log中node-2 commit增长曲线(15→27, 35s)<br>3. 对比Raft标准参数推荐值<br>4. 产出根因报告 |
| **产出** | 根因报告（含参数现状、35s成因分析、修复建议） |
| **约束** | 根因分析阶段禁止修改任何代码 |

### R-02 选举稳定性

| 项 | 内容 |
|---|---|
| **目的** | 验证选举超时参数在5节点拓扑下是否合理，是否存在选举风暴风险 |
| **步骤** | 1. 只读诊断：读取选举超时配置<br>2. 分析E01b中Leader崩溃→新Leader当选耗时<br>3. 对比TCX-Ⅱ-1 50节点选举风暴风险依据<br>4. 产出评估报告 |
| **产出** | 选举稳定性评估报告 |
| **约束** | 根因分析阶段禁止修改任何代码 |

### R-03 写路径deadline传递

| 项 | 内容 |
|---|---|
| **目的** | 验证写路径（propose→commit→WAL）是否存在deadline缺失/传递中断 |
| **步骤** | 1. 只读诊断：读取propose处理链/WAL flush超时配置<br>2. 分析写路径各阶段是否有context.Deadline<br>3. 评估高负载下写路径超时风险<br>4. 产出评估报告 |
| **产出** | 写路径deadline评估报告 |
| **约束** | 根因分析阶段禁止修改任何代码 |

### P-Ⅰ 修复与回归

每个专项(R-01/R-02/R-03)流程：
1. 根因报告（只读诊断）
2. 修复（需批复后执行，修复diff单独commit）
3. 重跑E01b/E02回归
4. 新收敛耗时达标≤5s或给出归因

### P-Ⅰ 通过标准

- 35s收敛根因定位完成
- 修复后E02收敛耗时≤5s，或给出无法进一步优化的归因
- E01b/E02回归PASS

## P-Ⅱ 性能压测

### 前置条件

P-Ⅰ完成（稳定性根治后参数已优化），否则压测结果反映的是次优参数下的性能。

### 指标锚定（依据来源）

| 指标 | 锚定值 | 依据来源 | 口径 |
|------|--------|---------|------|
| 分布式基线TPS | 36,461 req/s | 鲲鹏v1.0.0实机 (kunpeng-evidence/04) | 500并发/120s |
| 分布式基线P99 | 127.4ms | 同上 | 同上 |
| 故障自愈对照TPS | 5,240 TPS | 鲲鹏v1.0.0分布式 (kunpeng-evidence/06) | 30并发/60s |
| 故障自愈对照P99 | 49ms | 同上 | 同上 |
| 规模风险依据 | 50节点选举风暴 | TCX-Ⅱ-1 (kunpeng-evidence/07) | 100并发/30s, 写入成功率0% |
| 并发风险依据 | 1000并发Max=20s | TCX-Ⅱ-4 (同上) | 1000并发/300s |

> **禁止**引用v1.0.0单机73万TPS作为分布式目标。v1.0.0为单机极限口径，与分布式5节点不可横向比较。

### 环境差异声明

| 维度 | 鲲鹏实机 | 本地Docker |
|------|---------|-----------|
| CPU | 鲲鹏920 ARM64 | x86_64 18逻辑核 |
| 网络 | 裸金属直连 | Docker bridge |
| 部署 | 3台混部5节点 | 单机Docker 5容器 |
| 数据落盘 | MySQL异步 | WAL(SM4加密) |

鲲鹏数据为锚定参照，本地Docker实测值按环境差异折算后与锚定值对照。

### P-Ⅱ 用例定义

#### E04 [起草] 基线复刻对照

| 项 | 内容 |
|---|---|
| **目的** | 在本地Docker 5节点复刻鲲鹏v1.0.0压测口径，与36,461 req/s锚定值对照 |
| **步骤** | 1. 5节点集群正常运行<br>2. 500并发/120s混合读写(80%读+20%写)<br>3. 记录TPS/P99/P50/成功率<br>4. 与鲲鹏锚定值对照，计算环境折算比 |
| **预期** | 产出本地基线TPS和折算比，成功率≥99% |
| **证据格式** | `E04/result.txt`: TPS/P99/P50/成功率/折算比<br>`E04/raw.csv`: 原始数据 |

#### E05 [起草] 故障期性能

| 项 | 内容 |
|---|---|
| **目的** | 验证故障期间（分区/节点崩溃）性能退化，与5,240 TPS/49ms对照 |
| **步骤** | 1. 5节点集群正常运行，持续30并发写入<br>2. 断开一个follower网络<br>3. 持续60秒记录TPS/P99<br>4. 恢复网络，记录收敛耗时<br>5. 与鲲鹏故障自愈对照(5,240 TPS/49ms)比较 |
| **预期** | 故障期间TPS不低于锚定值×折算比×0.8，恢复后收敛达标 |
| **证据格式** | `E05/result.txt`: 故障期TPS/P99/收敛耗时/对照结论 |

#### E06 [起草] 规模阶梯5→10→20

| 项 | 内容 |
|---|---|
| **目的** | 探测节点规模上限，验证5节点是否为最优生产规模 |
| **步骤** | 1. 5节点基线TPS（E04产出）<br>2. 扩展至10节点，同口径压测<br>3. 扩展至20节点，同口径压测<br>4. 对比TPS/选举稳定性/同步延迟 |
| **预期** | 产出规模-TPS曲线，确认5节点为生产规模或给出扩展建议 |
| **风险依据** | TCX-Ⅱ-1: 50节点选举风暴, 写入成功率0% |
| **证据格式** | `E06/result.txt`: 各规模TPS/稳定性/结论<br>`E06/scale-curve.csv`: 规模曲线 |

#### E07 [起草] 长尾上界

| 项 | 内容 |
|---|---|
| **目的** | 测量极端并发下的延迟长尾上界（P99.9/Max），评估是否可控 |
| **步骤** | 1. 5节点集群正常运行<br>2. 梯度加压至1000并发<br>3. 记录P99.9/Max延迟<br>4. 与TCX-Ⅱ-4风险依据(Max=20s)对照 |
| **预期** | Max延迟远低于20s风险线，P99.9可控 |
| **风险依据** | TCX-Ⅱ-4: 1000并发Max=20.05s |
| **证据格式** | `E07/result.txt`: P99.9/Max/风险对照结论 |

#### E08 [起草] 2h长稳0失败

| 项 | 内容 |
|---|---|
| **目的** | 验证5节点集群2小时持续写入零失败、无内存泄漏、TPS无衰减 |
| **步骤** | 1. 5节点集群正常运行<br>2. 以基线并发×0.8持续写入2小时<br>3. 每60秒记录TPS/commit/内存/失败数<br>4. 检查：0失败、TPS波动<10%、内存稳定 |
| **预期** | 2小时0失败，TPS波动<10%，内存无持续增长 |
| **证据格式** | `E08/result.txt`: 总TPS/总条数/失败数/内存趋势/结论<br>`E08/timeline.csv`: 每60秒采样 |

### P-Ⅱ 执行顺序

E04(基线复刻) → E05(故障期) → E06(规模阶梯) → E07(长尾上界) → E08(2h长稳)

### P-Ⅱ 通过标准

- E04: 本地基线TPS产出，折算比确定，成功率≥99%
- E05: 故障期性能不低于锚定×折算×0.8
- E06: 规模-TPS曲线产出，生产规模确认
- E07: Max延迟远低于20s风险线
- E08: 2小时0失败，TPS波动<10%
