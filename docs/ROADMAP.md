## 方向穷举（六项）

### 1. 可观测性增强

| 字段 | 内容 |
|------|------|
| **价值** | 高：当前缺选举轮次计数/分区期间心跳丢失计数等指标，网络分区验证需仪表先行 |
| **成本** | 中：补端点 + 测量用例，约 2 批次 |
| **依赖** | 无 |
| **quorumbench 侧** | quorumbench 有独立指标采集，本仓库需对齐 |
| **优先级** | **P0**（网络分区验证前置） |

### 2. 网络分区注入

| 字段 | 内容 |
|------|------|
| **价值** | 高：验证 Raft 在网络分区下的安全性/可用性，核心共识协议验证 |
| **成本** | 高：注入点选择 + timing 控制 + chaos_injector 扩展 + 验收，约 3-4 批次 |
| **依赖** | 可观测性增强（P0），regression.yaml 扩充 |
| **quorumbench 侧** | quorumbench 有网络分区测试套件，可作双轨对照 |
| **优先级** | **P1** |

### 3. 回归体系扩充

| 字段 | 内容 |
|------|------|
| **价值** | 中：regression.yaml 5→8 条已扩，后续需持续收编新达成线 |
| **成本** | 低：每批追加 1-2 条，渐进式 |
| **依赖** | 无 |
| **quorumbench 侧** | quorumbench 有独立回归门，可双轨校验 |
| **优先级** | **P2** |

### 4. quorumbench 双轨

| 字段 | 内容 |
|------|------|
| **价值** | 中：独立平台交叉验证，提高判定可信度 |
| **成本** | 低：首跑基线已产出，后续每轮跑一次 |
| **依赖** | quorumbench 平台可用性 |
| **quorumbench 侧** | 已有标准验收套件 |
| **优先级** | **P2** |

### 5. 文档整理

| 字段 | 内容 |
|------|------|
| **价值** | 低：现有文档分散在 evidence/ 和 docs/，需归档整理 |
| **成本** | 低：纯文档工作，约 1 批次 |
| **依赖** | 无 |
| **quorumbench 侧** | 不涉及 |
| **优先级** | **P3** |

### 6. 开源准备

| 字段 | 内容 |
|------|------|
| **价值** | 低（当前阶段）：代码清理 + LICENSE + CONTRIBUTING + CI/CD |
| **成本** | 中：需移除内部依赖 + 敏感配置 + 补开源文档 |
| **依赖** | 文档整理 |
| **quorumbench 侧** | 不涉及 |
| **优先级** | **P3** |

## "暂不做"清单及理由

| 方向 | 理由 |
|------|------|
| Raft 协议层改选（检查点选举/预选 leader） | 超出当前范围，需协议设计评审，成本过高 |
| 存储引擎替换（LSM-tree 替代 WAL） | 当前 WAL + group commit 已满足性能需求，fsync 非瓶颈 |
| 跨集群复制 | 当前单集群 5 节点已满足可用性需求 |
| 客户端 SDK 重写 | loadgen 已修复，当前聚焦服务端 |
| 多租户隔离 | 当前无多租户需求 |
| 快照分片/流式合并 | io.ReadAll O(N) 为已知技术债，当前 30min 浸泡达标，非紧急 |
